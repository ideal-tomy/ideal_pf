# 建設ページ 原稿とデモの照合記録

確認日：2026年9月12日

## 確認対象と方法

- 公開デモ：https://construction-demo-six.vercel.app/
- ローカル本体：../construction_demo の README、PhotoSortDemo、report/page、WorkflowActions、opsSample等を読み取り。
- 公開デモをブラウザで操作し、サンプル写真整理→下書き→修正→確認→提出→管理側の確認済み表示まで確認。
- 実写真の送信、実AIによる解析、実担当者への送信は実施していない。
- 紹介ページは ideal_pf の既存 ?demo=construction-record を維持し、建設専用の詳細表示を追加。独立ルートへの移行や外部デモ本体の変更は今回の対象外。

## 公開デモで確認できたこと

| 操作 | 実際に確認した表示・変化 | 原稿への反映 |
|---|---|---|
| ハブを開く | 写真の仕事化、報告書・朝礼下書き、現場オペの3入口 | 3段階をつなぐ体験と、気になる作業を選ぶ入口を併設 |
| 写真の「整理する」 | IMGの名前から、現場A・工種・日付を含む名前へ。基礎工事・鉄筋工事・型枠工事・安全管理へ分類 | 「工種を入力する」ではなく「分類・命名の前後を見る」へ修正 |
| 「報告書下書きへ」 | /report?from=photo に移動。4枚の整理済み写真がテンプレートに反映 | 写真整理から下書きへ進む案内を採用 |
| 「AIで下書き」 | サンプルの案件名・作業内容等が表示。天候と要請事項に要確認表示 | サンプル文章が入ること、人が内容を確認することを明記 |
| 天候欄の修正→「確認する」 | 「晴れ（サンプル確認）」への変更が正式帳票の天候欄に反映 | 確認・修正の体験を価値として紹介 |
| 「提出する」 | 提出状態に変化し「管理画面で確認」が表示 | 提出後の管理側確認へ案内 |
| 管理画面→新しい通知を開く | 現場A・基礎工区の通知と、4枚の写真・案件・作業内容等を確認 | 現場と事務の引き継ぎを紹介 |
| 「確認済みにする」 | 通知に「確認済」の表示 | 確認状況を見る体験として記載 |
| 管理画面の不足写真一覧 | 配筋の接写・安全看板と「催促」ボタンを確認 | 催促画面の入口を紹介。実送信を示唆しない |

## コードで補足した範囲

- 写真整理は固定サンプルとタイマーによる演出。
- 写真整理から進んだ報告書の下書きはサンプルデータの複製。実AI解析とは別。
- 提出から管理画面への引き継ぎは sessionStorage を利用。実サーバー保存・実担当者への連絡ではない。
- モバイルの報告書入口には「体験をはじめる」がある。
- PDF保存は印刷機能を利用する実装だが、保存ファイルの検証は今回行っていないため、主な価値や手順の訴求には含めていない。
- 要確認表示は全誤りの検出を保証しない。確認ボタンを押せることと記載内容の正しさを区別する。

## 今回採用しなかった表現

- 実画像の分類精度や解析の成功率、具体的な時間・コスト削減率。
- 自動で間違いをすべて検出する、確認不要で完成するという表現。
- 自社の指定書式にそのまま対応するという表現。
- 写真整理の画面で工種や場所を利用者が入力できるという旧紹介文。
- 回数・費用上限の未確認の数値。実画像解析の上限明示は引き続き内部改善管理の課題とする。
