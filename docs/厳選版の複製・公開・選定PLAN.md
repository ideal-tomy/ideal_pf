作成日：2026-09-20  
状態：計画。複製・デプロイ・掲載内容の変更は未実施。

## 1. 目的と確定方針

現在の `ideal_pf` は、全件を閲覧できる一覧版としてそのまま残す。
別プロジェクトへ同じ状態で複製し、別の公開先へデプロイした後に、掲載する5〜10件を検討する。

厳選版は名刺裏面のQRコードやURL共有から案内する、自社の技術・商材・開発紹介サイトとする。カード形式のトップと、アプリ紹介のような詳細ページから実際のデモへ進む体験を活かす。

**作業順序は「同じ状態で複製 → 別デプロイ → 同等性確認 → 厳選内容の検討 → 改善・構成変更」とする。複製と同時に選定や削減を行わない。**

## 2. プロジェクトの役割

| 項目 | 既存の一覧版 | 新しい厳選版 |
|---|---|---|
| ローカル | `C:/Users/ryoji/00myapp/ai_demo_workspace/ideal_pf` | `C:/Users/ryoji/00myapp/ai_demo_workspace/ideal_pf_selected`（仮称） |
| 役割 | 全件カタログとして維持 | 名刺・URL共有から案内する紹介サイト |
| 初回の内容 | 現状維持 | 既存版と同じ内容・構成 |
| 選定後の内容 | 現状の一覧を維持 | 厳選した5〜10件 |
| デプロイ | 現在の公開先を維持 | 独立した新規プロジェクト・公開URL |

当面は独立したコピーとして管理し、共通パッケージ化やデータ同期の仕組みは作らない。厳選版を変更しても既存版に影響しないことを優先する。

紹介サイトの複製と、リンク先のデモ本体の複製は別の作業とする。初回は既存と同じ外部デモURLを使用する。後でデモ本体を改修する場合は、一覧版からも同じデモにアクセスすることを踏まえ、共通改善か別版作成かを個別に判断する。

## 3. フェーズ1：同じ状態で複製する

### 作業

- 既存版のソース、掲載データ、画像、設定、依存関係、Gitの状態を確認する。
- 複製元のコミットID・未コミット変更の有無・作業日時を記録し、ローカルの現在の状態を基準にする。
- 新規ディレクトリへ、ソース・公開アセット・必要な設定・ロックファイルを複製する。
- `.git`、`.vercel`、`node_modules`、`dist` は引き継がず、新しい管理情報・依存環境・ビルド成果物を用意する。
- 環境変数が必要な場合は用途を確認し、新しい公開先へ適切に設定する。秘密情報をリポジトリへ追加しない。
- 新しいGit管理・必要に応じた独立リポジトリを用意し、複製直後の状態を記録する。
- 依存関係をロックファイルに従って導入し、ビルドする。

### この段階で維持するもの

- 掲載28件と現在のトップカード・並び順
- 全件一覧、検索、業種別表示、ナビゲーション

- 外部デモURL、詳細を共有するURL形式
- 見た目と操作の挙動

複製に必要な識別情報以外は変更しない。機能改善や依存パッケージの更新は別作業にする。

### 完了条件

- 新しいディレクトリだけでビルドできる。
- 既存版のアプリ・掲載データ・デプロイ設定を変更していない。
- コピー対象ファイルの比較で、意図しない差分がない。
- ローカルでトップ・一覧・詳細が既存と同じ内容で表示される。

## 5. フェーズ3：厳選する5〜10件を検討する

このフェーズは、同じ状態での別デプロイと確認が完了してから開始する。現時点で掲載デモを確定しない。

### 選定手順

1. 名刺を渡す相手、紹介したい商材、受けたい開発相談を整理する。
2. 全28件を短く確認し、課題・体験内容・重複・修正量を記録する。
3. 有力候補について、スマホとPCで実際の操作を確認する。
4. 「掲載候補」「改善後の候補」「今回の厳選版には掲載しない」に分類する。
5. テーマの重複と開発能力の伝わり方を見て、5〜10件と予備候補を決める。
6. 掲載候補ごとに、公開までの修正内容と完成条件を決める。

既存の分類・改善記録は参考資料として利用するが、過去の評価だけで採否を決めない。公開URLが開くことと、操作を完走できることは分けて評価する。

### 選定基準

| 観点 | 確認すること |
|---|---|
| 営業との適合 | 実際に紹介したい相手や受けたい相談に合っているか |
| 課題の明確さ | 誰の、どの仕事を、どう改善するか説明できるか |
| 体験の完成度 | 入力・選択から結果の確認まで進めるか |
| 自由操作の品質 | 表示中のボタンや画面を触っても行き詰まらないか |
| 説明との一致 | 紹介文・画像・実際の機能が一致するか |
| スマホ対応 | QRから開いて内容を理解し、代表操作を試せるか |
| 独立掲載の意味 | 他の掲載候補と異なる価値や開発能力を示せるか |
| 改善・維持の負担 | 公開品質までの修正と、その後の維持が現実的か |

件数を満たすために品質基準を下げない。まず5件を揃え、基準を満たすものがあれば10件まで広げる。

### 成果物

- 全28件の選定表と採否理由
- 厳選する5〜10件および予備候補
- 各候補の代表体験・改善項目・掲載合格条件
- 改善の着手順

## 6. フェーズ4：選定後に厳選版を仕上げる

### サイト構成

- トップに厳選した5〜10件をカードで掲載する。
- カードからアプリ紹介風の詳細ページへ進み、実際のデモへ案内する。
- 全件一覧ページと業種検索など、一覧へ進むための導線を厳選版から外す。
- 会社紹介・開発の進め方・相談先は、トップまたは詳細内に必要な分だけ配置する。
- 関連デモも厳選対象に揃える。
- 掲載対象外の詳細URLや旧一覧URLを開いた際の案内を決める。
- 件数表示、共有情報、見出しを厳選版の内容に合わせる。

### デモと紹介の仕上げ

- 代表1件で「カード → 詳細 → デモ体験 → 相談」の完成形を作る。
- 同じ基準で残りの掲載候補を仕上げる。
- 体験できない機能や誤解を招く説明を整理する。
- 固定サンプル、保存範囲、利用条件を実際の挙動に合わせて説明する。
- 相談先と会社サイトへのリンクを実際に利用できる状態にする。
- 販売する商材か、個別開発の参考デモかを必要に応じて明示する。

### 完了条件

- 掲載する全デモが共通の品質基準を満たす。
- 紹介から体験、相談までの導線が機能する。
- 一覧版の内容と公開先は維持されている。

## 7. フェーズ5：名刺・URL共有で使い始める

- 名刺配布後も同じURLを維持し、掲載内容を更新する。
